## Context

阶段 1 已经建立本地 `.venv` 环境，阶段 2 已经完成 GSM8K 数据初始化、数据结构检查和标准答案抽取。当前项目已经有 `src/gsm8k_dataset.py`，其中的标准答案抽取函数可以把 GSM8K `answer` 字段里的 `#### final_answer` 转成干净字符串。

阶段 3 是从“能抽取标准答案”进入“能给模型输出打分”的过渡。这个阶段的关键不是训练模型，而是把 reward 逻辑做成可读、可测、可复用的小模块，为后续 TRL `GRPOTrainer` 提供清晰的函数边界。

## Goals / Non-Goals

**Goals:**

- 规定一个简洁的模型输出格式：`<reasoning>...</reasoning><answer>...</answer>`。
- 实现从模型 completion 中抽取 `<answer>` 内容的函数。
- 实现轻量数值等价判断，覆盖 GSM8K 入门阶段常见的整数、小数、分数和带逗号数字。
- 实现正确性 reward，能比较模型答案和 GSM8K 标准答案。
- 实现格式 reward，鼓励模型输出包含推理段和答案段。
- 提供离线检查脚本，用手写样例验证 reward 行为。
- 更新文档，让学习者知道阶段 3 如何运行、如何验收、哪些内容还没进入本阶段。

**Non-Goals:**

- 不下载或加载模型权重。
- 不运行模型生成、baseline inference、GRPO 训练或独立评估。
- 不引入 Math-Verify、SymPy 或其他复杂数学验证依赖。
- 不支持 LaTeX、单位换算、符号表达式、多答案集合或证明题验证。
- 不引入 vLLM、Ray、DeepSpeed、FSDP、verl、OpenRLHF 或多 GPU 框架。

## Decisions

1. Reward 逻辑放在 `src/`，学习入口放在 `scripts/`。

   `src/` 中的 reward 模块提供可复用函数，例如模型答案抽取、数值等价、正确性 reward 和格式 reward；`scripts/` 只负责运行硬编码样例并打印结果。这样后续训练脚本可以直接导入同一套 reward 函数，避免把训练和验证逻辑揉在一起。

   备选方案是把 reward 全部写进一个检查脚本里。这样更快，但后续接入 GRPO 时会复制逻辑，不利于学习每个组件的职责。

2. 模型答案抽取只依赖 XML-like 标签。

   阶段 3 约定 `<answer>...</answer>` 是模型最终答案位置，抽取函数只返回该标签中的内容；缺少标签或标签为空时返回空字符串。`<reasoning>` 主要用于格式检查，不参与正确性比较。

   备选方案是从最后一行或自然语言中猜答案。这会让早期 reward 变得不透明，模型也更容易利用模糊规则。

3. 数值等价先用 Python 标准库实现。

   使用 `fractions.Fraction` 和基础字符串清理处理整数、小数、分数和逗号数字。例如 `1,000` 与 `1000` 等价，`0.5` 与 `1/2` 等价。解析失败时回退到清理后的字符串相等。

   备选方案是立即接入 Math-Verify 或 SymPy。它们对后续复杂数学题有价值，但会显著扩大阶段 3 的学习范围，也可能把 reward 行为隐藏到外部库里。

4. Reward 返回简单浮点分数。

   正确性 reward 对等价答案返回 `1.0`，否则返回 `0.0`。格式 reward 对完全符合格式的 completion 返回 `1.0`，否则返回 `0.0`。本阶段先保持二值 reward，便于手工检查。

   备选方案是设置多级格式分，例如有 `<answer>` 给 0.5、完整格式给 1.0。多级格式奖励可在后续训练稳定性需要时加入；当前阶段先把行为做清楚。

5. 离线检查是本阶段的主要验收方式。

   检查脚本使用硬编码样例覆盖：正确答案、错误答案、分数与小数等价、逗号数字等价、缺失标签、格式不完整。它不下载数据集、不下载模型、不依赖网络。

   备选方案是直接读取 GSM8K 样例做 reward 检查。那也可以作为补充，但离线硬编码样例更适合验证边界条件。

## Risks / Trade-offs

- [Risk] 轻量数值等价无法覆盖 LaTeX、单位、符号表达式或复杂数学答案 -> Mitigation: 文档明确阶段 3 只覆盖 GSM8K 入门样例，复杂验证留给 Math-Verify 阶段。
- [Risk] 严格标签格式会让早期模型输出大量拿不到格式分 -> Mitigation: 训练前先通过 prompt 约束输出格式；必要时后续再扩展部分格式分。
- [Risk] 二值 reward 太粗，后续训练信号可能稀疏 -> Mitigation: 阶段 3 只验证逻辑正确性；阶段 4 接入训练后再根据日志调整 reward 粒度。
- [Risk] 字符串回退比较可能误判语义等价答案 -> Mitigation: 回退只作为解析失败的保守处理，不宣称支持通用数学验证。
